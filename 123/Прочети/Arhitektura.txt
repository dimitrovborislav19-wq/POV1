1. Какво всъщност анализирахме

Анализирахме обфускирано .NET приложение, в което licensing логиката не стои на едно място, а е разделена на няколко слоя:

локален licensing/state слой
startup/orchestration слой
remote HTTP licensing client
request/response pipeline
signature/integrity seam
runtime state и UI consumers

Основният извод е, че това не е проста лицензна проверка в един метод, а многостепенна архитектура.

3. Най-важните открити типове и ролята им
A) rUUTMOy6ivNnYRiNMr63

Това е най-важният клас, който намерихме.

Ролята му е:

startup license coordinator
local license manager
runtime state manager
bridge между local old model и newer remote model
persistence orchestration
file watcher / reactive state updater

Това не е просто UI class и не е DTO.
Това е централен operational/service слой.

B) OldCpLicense

Това е локалният legacy licensing model.

5. Защо ни беше трудно да стигнем до “тялото”

Причините бяха 3 едновременно:

1. Обфускация

Имената са разрушени и не можеш да четеш естествено потока.

2. Async state machine compilation

Реалната логика не е в:

Asmy84GEo1V
urpyBRyGunV
JMjyBO4Y9Pe

а в generated типове като:

<GetLicenseInfoAsync>d__7
<ProcessResponseAsync>d__12
<IsSignatureValid>d__13
<ReadObjectFromResponseAsync>d__14
3. dnSpy navigation quirks

Когато натискаш MoveNext, dnSpy често те връща към wrapper метода, а не отваря красивото тяло на state machine-а.
